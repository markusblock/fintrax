# FinTS sync reconciles pending entries only from complete responses

Use a valid German IBAN to derive BLZ and account number. Store bank identity and FinTS connection settings in a shared Bank profile, matched by BLZ; keep BIC as optional Bank metadata. Resolve a missing FinTS Server Address from the local HBCI4Java bank directory using BLZ. Directory lookup is local and does not contact the bank. Store FinTS User ID and optional Customer ID on Bank; never infer either from account holder/import data. Use FinTS `KUmsAll` without a client-selected start date so the bank-supported history window bounds each repeated sync; transaction matching follows ADR-0004. Import booked and pending transactions, update matching pending entries when they become booked while preserving Fintrax-owned fields, and remove unmatched pending entries only after HBCI execution, the transaction job, and mapping every returned row succeed. Request password/PIN for each Bank sync without storing it; a Sync All reuses one entered secret across that Bank's accounts. Abort unsupported TAN challenges without sending a response, retain TLS certificate validation, and avoid logging financial data. Failure diagnostics may include a safe category, exception type, and stack frames, but not exception messages or financial data. Persistent credential storage remains a separate decision tracked by #146.

This may retrieve more history than a narrow incremental window, but avoids fixed-window gaps and keeps stale pending cleanup tied to complete bank data.
